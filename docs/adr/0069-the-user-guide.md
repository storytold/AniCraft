# ADR 0069: The user guide: Markdown chapters, generated references and a bundled HTML book

* Status: accepted (2026-11-11)
* Relates to: ADR 0004 (destructive actions), ADR 0005 (typography), ADR 0006 (platforms),
  ADR 0036 (web build), ADR 0040 (interface languages), roadmap M8 ("documentation book")

## Context

M8 ends with a documentation book. Until now AniCraft's documentation was written for
contributors (`docs/*.md`, the ADRs) and the in-app help was the command palette, the shortcut
editor and tooltips. Artists, many of them coming from Adobe Animate, need a guide written for
them: where things are, how to do common tasks, what works differently from Animate, and what
isn't there yet. It must work offline from the app, match the version it ships with, and not rot.

## Decision

1. **Chapters are Markdown in `docs/guide/`**, one file per chapter, readable on GitHub as they
   are, in plain English for artists (British spelling, as the rest of the docs; no ADR numbers or
   crate names). `index.md` is the contents page. A "Coming from Animate" chapter maps Animate's
   panels, tools and shortcuts to AniCraft's, with nominative use of the names only
   (`docs/legal/compliance.md`) and the non-affiliation line.
2. **The references are generated, never written by hand.** `reference/commands.md` lists every
   `CommandSpec` by top menu (label, id, submenu, default key with its macOS spelling, whether it
   changes the document, parameters). `reference/shortcuts.md` lists every default key by the
   shortcut editor's groups (registry shortcuts and aliases, tool keys, view keys and the fixed
   keys), in Windows/Linux and macOS columns through `platform::shortcut_label_for`. They are
   generated by the shell (`src/guide_reference_tests.rs`), because the tool keys, view keys and macOS
   labels live there. Tests compare them with the committed files and fail when they are stale,
   with the command that regenerates them: `ANICRAFT_BLESS_GUIDE=1 cargo test -p anicraft
   guide_reference`. We chose committed, checked files over generating at build time so the
   pages read on GitHub and diffs in pull requests show what a command change does to the docs.
3. **A new L0 crate, `anicraft-guide`, builds the book.** It compiles every chapter and picture in
   (`include_str!`, `include_bytes!`), renders them with `pulldown-cmark` (MIT, CommonMark with GFM
   tables; default features off) into static pages with one stylesheet, a chapter list and
   previous / next links. `.md` links become `.html` links; headings get GitHub's anchor ids, so
   one link works on GitHub and in the book. Raw HTML in the Markdown is escaped, never passed
   through. We chose a maintained CommonMark parser over our own Markdown subset: the spec's edge
   cases (nested lists, emphasis, tables) are where a hand-written one goes wrong, and the crate is
   small, permissive and has no unsafe-heavy or native dependencies.
4. **The book is checked like code.** `anicraft_guide::check` fails on a broken link, picture or
   anchor; a link that leaves the book (only `https:` links may point outside it); a page the
   contents page can't reach; a page without exactly one title; raw HTML; and an unused picture.
   Tests also require that `docs/guide` and the book's page and picture lists match, and that
   pictures stay PNGs under 300 KB.
5. **Help › User Guide opens it in the browser, offline.** On the desktop the app writes the
   bundled book to a version-named folder in the system cache (`platform::guide_dir`:
   `%LOCALAPPDATA%`, `~/Library/Caches`, `$XDG_CACHE_HOME`) and opens `index.html` with the system
   handler; rendering and writing the 29 files (2.2 MB) takes 46 ms for a whole `anicraft-cli guide`
   run (debug build, Windows), and keeps the pages exactly those of
   the running version. The web build doesn't carry the book in its download:
   `scripts/build-web.sh` writes it next to the editor with `anicraft-cli guide --out web/guide`,
   and the menu item opens `guide/index.html` in a new tab. The item is also in the command
   palette. It is a shell action, like the other Help items; the headless equivalent is
   `anicraft-cli guide`.
6. **Screenshots are few, reproducible and small.** `scripts/guide-shots.sh` / `.ps1` take eight
   pictures from `--screenshot --open <state>` runs at the fixed 1600 × 940 window in English, scaled
   to 1100 px across with the new `--shot-width` flag (an area-weighted box filter, so text stays
   crisp). They are original work, listed in `ATTRIBUTION.md`.
7. **The guide is English for now.** The interface is translatable (ADR 0040); translating the
   guide needs a translation workflow for long prose, which is later work. The book's language is
   declared (`lang="en"`).

## Consequences

* Changing a command's label, menu, shortcut or parameters fails a test until the reference is
  regenerated, so the guide's references can't drift from the app.
* Renaming a heading that another chapter links to fails the link check.
* The desktop binary grows by the book's size (about 2 MB, nearly all screenshots).
* Writing chapters stays a documentation task: no build step is needed to read them on GitHub.

## Not yet

* Translated guides, search inside the book, and a printable single-page or PDF edition.
* Context help (a "?" in a panel opening its chapter at the right heading).
* Screenshots on macOS and Linux, and in high contrast.
